1. Product definition
FinSafe AI is an AI financial risk copilot for SMBs. It connects to accounting and ERP systems, detects fraud and financial risk, predicts cash problems, and tells the owner what to do this week.
USP (put this on the home page):
One risk view across Zoho Books, NetSuite, and Odoo, unified into a single schema.
Predicts, not just reports: cash runway forecast and what-if simulator.
Catches fraud and anomalies: duplicate invoices, vendor price spikes.
Trustworthy AI: all numbers computed by code, Gemini only explains. Every alert shows evidence.
Read-only and human-in-the-loop: it drafts, you approve.

Unified schema (keep it minimal)
Invoice: id, customer, amount, issue_date, due_date, paid_date|null, status, source
Bill: id, vendor, amount, issue_date, due_date, paid_date|null, status, source
Payment (optional): date, amount, direction
CashAccount: current_balance
Insurance policy is optional. Skip it unless you finish early.

Engine specs (deterministic logic)
Cash runway (cash.py): Start from current balance. Build a day-by-day projection for 90 days: add unpaid invoices on due_date (shifted by that customer’s average delay), subtract unpaid bills on due_date, subtract average recurring daily operating spend (from the last 90 days of paid bills). Runway is the first day the balance goes below 0. Return the daily series (for the chart), the runway day, and the top drivers.
Duplicates (duplicates.py): Flag invoice or bill pairs with the same counterparty and same amount within 7 days, or amounts within 1% with similar numbering. Return both IDs as evidence.
Vendor price spike (vendor_spike.py): For each vendor, compare the latest bill with the median of the previous bills. Flag if more than 25% higher.
Late-payment risk (late_pay.py): Per customer, calculate average days late and the share of invoices paid late. Score as risk = 0.6*late_ratio + 0.4*min(avg_days_late/30, 1). Rank customers.
Health score (score.py): Start at 100. Subtract points for short runway (for example under 30 days: -35, under 60: -20), each high-severity finding, and a high overdue receivables ratio. Clamp 0-100.
Finding object (every engine returns this shape)
json
{
  "id": "f_001",
  "type": "duplicate_invoice",
  "severity": "high",
  "title": "Possible duplicate invoice",
  "amount_at_risk": 84500,
  "evidence": ["INV-1042", "INV-1047"],
  "explanation": null
}
Gemini layer (gemini.py), three functions only
explain(findings, summary): system prompt says “You are a financial risk analyst. Use ONLY the numbers provided. Never compute or invent figures. Explain each finding in 2 sentences and give one action. Return JSON.”
draft_email(invoice, customer_stats): polite, firm collection email.
chat(question, analysis_json): answer only from the analysis JSON, otherwise say it doesn’t have that data.
Synthetic dataset (demo_data.json): One fictional company, “Sharma Distributors”. 12 months of invoices and bills. Plant these on purpose:
A duplicate invoice pair (same customer, same amount, 3 days apart).
A vendor price spike (one vendor’s latest bill about 40% above its median).
A chronically late customer (pays about 25 days late on average, with a large open invoice).
A cash crunch about 6 weeks out (big bills landing before big receivables).
Current balance sized so runway is about 40-50 days.

Zoho live connector (only if time allows)
Use the Zoho API Console, create a Self Client, and generate a grant token with scopes ZohoBooks.invoices.READ, ZohoBooks.bills.READ, ZohoBooks.settings.READ. Exchange it for access and refresh tokens, and store them in env vars.
Call GET https://www.zohoapis.in/books/v3/invoices?organization_id=... (use the data-center domain matching your account: .in, .com, .eu).
Map the response to your Invoice and Bill schema.
In the UI, the Zoho “Connect” button can trigger this and show “Connected” on success. Anything beyond this is stretch.
